CAMINO MSS DELIVERY PLAN
=========================

Last Updated: 10 Feb 2026
Sprint Duration: 1 week
Builder: Solo
Model: Minimum Sellable Service (Admin-in-the-loop)
North Star: Customer pays after Week 2. Customer retains after Week 6.
First Customer: Uses Zoho CRM, Zoho Desk, and custom CSV data files.


USER PROBLEMS WE'RE SOLVING
-----------------------------

1. TOO SLOW
   Current company workflow is too slow to surface valuable information required for action.
   Desired Outcome: Increased speed to valuable information. Decrease time to produce reports, analyse information, find opportunities and risks.

2. SO WHAT?
   Lacking "so what" from managers who are providing data and reporting.
   Desired Outcome: Better business results from actions.

3. OVERWHELM
   Execs find it difficult to use current tools, which are analyst-first.
   Desired Outcome: Improved ease and intuitiveness in exploring valuable information.

4. EASY INTEGRATIONS
   Easy for team members to connect and update data. No IT department required.
   Desired Outcome: Decreased time to produce reports.


MSS USER STORIES (SCOPE)
==========================


US1: COLLECT USER CONTEXT
--------------------------

As Camino Admin, I collect user context during a discovery call and store it in the system, so that AI analysis is personalised and relevant.

Acceptance Criteria:
- Admin can input discovery call notes into a user's profile via Admin CP.
- Admin can update user profile fields at any time via Admin CP.
- System saves: full_name, role, organization, industry, business_context, upcoming_priorities, signal_preferences, company_stage, team_size, market, competitors.
- Profile data is used downstream by the AI analysis prompt (US6).


US2: USER PROFILE PAGE
------------------------

As a user, I can see a profile page that reflects what the system knows about me, so I trust it understands my context.

Acceptance Criteria:
- User sees: Role, What's Upcoming, Signal Preferences, Org Details.
- Profile is read-only. Only admin can edit.


US3: DATA INPUT WITH 3-QUESTION FLOW
--------------------------------------

As a manager (or admin on behalf of a user), I upload data files and answer 3 questions per tab, so the system correctly understands what was uploaded.

Acceptance Criteria:
- User can upload one or more CSV/XLSX files.
- For each tab, system prompts 3 questions:
  1. What does each row represent? (leads, deals, tickets, customers, events, agents, other)
  2. Which column is the main metric? (dropdown of numeric columns, or "just count rows")
  3. Which column is the date? (dropdown of date columns)
- Admin can upload on behalf of a user (selects org/user first).
- System normalises fields and stores data in a persisting org data layer.
- Multiple uploads accumulate, not replace.


US4: GENERATE AT LEAST 3 ACCURATE SIGNALS
-------------------------------------------

As a user, I see at least 3 signals generated from my data, with correct and verifiable values.

Acceptance Criteria:
- System reads data fields and user answers from US3 to determine which signals to create.
- Each signal has: name, value, trend direction, percentage change.
- Every signal shown has an explicit calculation spec (calcSpec). No guessed or heuristic calculations.
- Signals are saved to the database.


US5: SIGNAL CARD AND EXPANDED VIEW
------------------------------------

As a user, I can see signal info on a compact card and expand it for deeper AI analysis.

Acceptance Criteria:
- Card shows: category badge, signal name, change value, trend icon.
- Expanded accordion shows: data details (L2) and AI analysis (L3).


US6: AI 5-SECTION ANALYSIS WITH USER CONTEXT
----------------------------------------------

As a user, I see AI-generated analysis that is personalised to my role, priorities, and business context.

Acceptance Criteria:
- AI generates analysis with 5 sections:
  1. What We Found (factual data)
  2. What It Means (interpretation)
  3. So What (business impact)
  4. Opportunities
  5. Risks
- AI prompt includes user context: role, upcoming_priorities, signal_preferences, business_context, org industry, company_stage.
- Analysis is triggered on upload. Admin can re-trigger manually.
- Response is cached in signal_interpretations table.


US7: BROWSE SIGNALS
---------------------

As a user, I can scroll through all my signals in a list, with single card focus or stacked view.

Acceptance Criteria:
- Signal list scrolls vertically with single card focus.
- Toggle to grouped/stacked view for scanning breadth.


US8: ADMIN MANAGES USERS AND ORGS
-----------------------------------

As Camino Admin, I can create users, create orgs, and assign users to orgs without engineering involvement.

Acceptance Criteria:
- Admin can create a user (email, name, role, password).
- Admin can create an organisation.
- Admin can assign users to organisations.
- Admin can view what a user sees (view-as-user mode).


US9: APP IS DEPLOYED
---------------------

As a user, I access the app via a production URL, not localhost.

Acceptance Criteria:
- App deployed on Vercel, accessible at a stable URL.
- Database running on Supabase + Neon.


DEFINITION OF BILLABLE (END OF WEEK 2)
----------------------------------------

The customer agrees to pay when ALL of these are true:

[ ] Manager can upload a CSV/XLSX and see it processed (US3)
[ ] System generates at least 3 signals with correct values (US4)
[ ] Each signal has AI analysis personalised to the user (US6)
[ ] Exec can browse signals and read expanded view (US5, US7)
[ ] Admin can create users and upload on their behalf (US8, US3)
[ ] App is deployed to production (US9)


RELEASE PLAN (6 WEEKS)
========================


RELEASE 1: ACCURATE SIGNALS (End of Week 1)
---------------------------------------------

Goal: The core pipeline works correctly. Upload a file, answer 3 questions, get accurate signals. No guessing.

What ships:
- 3-question upload flow replaces old discovery flow (US3)
- Signal definitions cut to ~20 core, all with calcSpecs (US4)
- Legacy heuristic calculation path removed (US4)
- Signal card displays correct values (US5)
- App deployed (US9)

Hypothesis to test: With user-clarified data and explicit calcSpecs, every signal value is correct and verifiable.


RELEASE 2: BILLING-READY (End of Week 2)
------------------------------------------

Goal: AI analysis is personalised. Admin can operate. Customer agrees to pay.

What ships:
- User context fields added to profiles table (US1)
- Admin CP form to input discovery notes into user profile (US1)
- User context injected into AI prompt (US6)
- AI analysis triggered on upload (US6)
- Profile page shows upcoming priorities and signal preferences, read-only (US2)
- Admin create user, create org, assign user to org confirmed working (US8)
- Admin upload-on-behalf-of-user (US3)

Hypothesis to test: Personalised AI analysis is the reason the customer agrees to pay. Generic analysis is not enough.


RELEASE 3: MULTI-FILE AND RETURNING UPLOADS (End of Week 3)
-------------------------------------------------------------

Goal: Org data layer persists across uploads. Returning uploads compare to previous.

What ships:
- Org data layer persists across multiple file uploads (US3)
- Returning upload recognition ("Comparing to previous...") (US3)
- Upload history visible to user and admin
- Cross-file signal discovery (e.g. conversion rate from Leads + Deals files)

Hypothesis to test: Accumulating data over time makes signals more valuable. Cross-file signals are a surprise-and-delight moment.


RELEASE 4: SIGNAL RELEVANCE (End of Week 4)
---------------------------------------------

Goal: Signals are ranked by what matters to the user. Filters help explore.

What ships:
- Signal ranking by user relevance (using role, upcoming_priorities, signal_preferences)
- Category filters on signals page (user, market, tech, business - when data types expand)
- Partial signal identification (system tells user what data is missing for signals it cannot compute)

Hypothesis to test: Ranking signals by relevance reduces overwhelm. Users engage more when top signals match their priorities.


RELEASE 5: ANALYSIS DEPTH (End of Week 5)
-------------------------------------------

Goal: Deeper analysis per signal. Trend visualisations. Benchmark framing.

What ships:
- Trend visualisation on signal detail (4+ weeks of data required)
- Section 6: KPI implication (how does this signal affect the user's stated KPIs)
- AI analysis references other signals for cross-correlation ("Ticket volume up 23%, which correlates with your 3 new hires")
- Admin AI review panel (approve, edit, regenerate interpretations)

Hypothesis to test: Cross-signal references and KPI framing make the analysis substantially more valuable than single-signal commentary.


RELEASE 6: RETENTION AND EXPANSION (End of Week 6)
----------------------------------------------------

Goal: The experience is polished and the customer is retained. Groundwork for second customer.

What ships:
- Progressive user context (system asks one new question per session to refine relevance)
- Upload reminders / nudges if no data uploaded in 7 days
- Admin dashboard with quality metrics (how many signals, AI accuracy, user engagement)
- QA pass on all signals and AI analysis for first customer
- Onboarding documentation for second customer

Hypothesis to test: The customer sees enough ongoing value to continue paying. The system is ready to onboard a second customer without re-engineering.

DECISIONS LOG
--------------

10 Feb 2026 - Pivoted from full MVP to MSS (Minimum Sellable Service)
  Rationale: Full productisation has blockers. Admin-in-the-loop bridges gaps while delivering enough value to bill.

10 Feb 2026 - 3-question upload flow replaces fuzzy signal discovery
  Rationale: User clarifies data type, metric column, and date column. Eliminates guessing. Every signal is grounded in confirmed understanding.

10 Feb 2026 - Cut from 93 signal definitions to ~20
  Rationale: 82/93 used heuristic calculations that produced wrong values. Fewer correct signals are better than many wrong ones.

10 Feb 2026 - User context in AI prompt is the billing differentiator
  Rationale: Generic AI analysis is not worth paying for. Personalised analysis based on role, priorities, and business context is.

10 Feb 2026 - 6-week release cadence with weekly demos
  Rationale: Tight feedback loops. Ship weekly, learn weekly. Customer sees progress every Friday.

7 Feb 2026 - 1-week sprint cycles
  Rationale: Solo builder. Tight feedback loops essential.

7 Feb 2026 - Dual database (Neon for signals, Supabase for auth)
  Rationale: Keep separation clean. Auth is Supabase-native. Signal data is relational on Neon.
