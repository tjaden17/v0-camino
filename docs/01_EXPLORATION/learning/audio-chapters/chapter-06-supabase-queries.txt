The Query Builder: Chainable Methods

The Supabase client provides a query builder that generates SQL behind the scenes. You chain methods to build complex queries.

The basic pattern starts with from:

This targets the signals table. Now you chain methods to specify what you want.

For SELECT queries, add dot select:

Selecting Relationships: Nested Queries

One of Supabase's most powerful features is fetching related data in a single query. Instead of multiple queries, you nest relationships in select.

This is much more efficient than fetching the signal, then fetching data points in a second query. One round trip to the database instead of two.

Error Handling: The data, error Pattern

Every Supabase query returns an object with data and error properties. One is always null.

If the query succeeds, data contains the result and error is null.
If the query fails, error contains the error object and data is null.

Always check error:

Don't assume data is valid. Check error first.

close brace

Error code 23505 is a unique constraint violation in Postgres. You can catch specific errors and show better messages.

Single Versus Multiple Results

dot single open parenthesis close parenthesis: Expect exactly one row. If there are zero or multiple rows, it's an error.

Use single when querying by ID or unique field:

const open brace data comma error close brace equals await supabase dot from open parenthesis quote signals quote close parenthesis dot select open parenthesis quote asterisk quote close parenthesis dot eq open parenthesis quote id quote comma signal id close parenthesis dot single open parenthesis close parenthesis

data is a single object, not an array.

dot maybe single open parenthesis close parenthesis: Expect zero or one row. If there are multiple rows, it's an error.

Use when a row might not exist:

const open brace data comma error close brace equals await supabase dot from open parenthesis quote signals quote close parenthesis dot select open parenthesis quote asterisk quote close parenthesis dot eq open parenthesis quote id quote comma signal id close parenthesis dot maybe single open parenthesis close parenthesis

If the signal doesn't exist, data is null and error is null. No error thrown.

Without single or maybe single, data is always an array, even if there's only one row.

Let's walk through a real query from your app. Open your signals page server component.

Common Query Patterns in Camino

Pattern 1: Fetch list with details.
Fetch signals with their data points and interpretations in one query. Use nested select.

Pattern 2: Fetch single item by ID.
Use dot eq open parenthesis quote id quote comma id close parenthesis dot single open parenthesis close parenthesis. Expect exactly one result.

Pattern 3: Paginated list.
Use dot range open parenthesis start comma end close parenthesis with calculated start and end based on page number.

Pattern 4: Filtered list.
Chain multiple dot eq, dot in, dot gte methods to filter by user input. Build the query conditionally based on what filters are applied.

Pattern 5: Upsert for sync.
Use dot upsert when syncing data from external APIs. If it exists, update it. If not, insert it.
